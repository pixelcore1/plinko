Plinko UI

The design system behind the Plinko reward minigame: tokens, components, motion, sound, haptics, physics and prize maths. One source for Figma and code.

Version 0.1.0Mobile first: 360 to 430 px, desktop tokens from 1024 pxDark themeWCAG 2.1 AA

Figma file: B2Spin Senior Product Designer Test Task (pages Foundation, Components, Assets, Plinko, Prototype notes). Every Figma variable has a CSS name (code syntax), and the CSS uses exactly these names. When a value changes in Figma, the export script rebuilds css/tokens.css.

Principles

Honest by design

The result is decided before the ball moves, with the natural odds of a real board. The ball then shows how it gets there. Risk changes the size of the prizes, never the chances, and the board shows this with a chance strip that stays the same at every level. Every drop wins something. There is no buy button, no autoplay and no fake near miss.

Celebration scales with the win

A small win is a toast and the game keeps going. A big win is a short sheet with a coin burst. Only a mega win (1 in 128) takes over the screen. This keeps the loop fast and saves the peak for the rare moment people remember. Every prize then flies into the winnings pool on the board, so the player always sees the total of the session.

Feels physical

Neon frame with bulbs, real gravity, peg flashes, a pitch that rises row by row, slow motion over the last rows. Sound and vibration follow the same events as the picture.

Works for everyone

Text contrast 4.5:1 or more, tap targets 44 px or more, keyboard support, screen reader labels. With reduced motion the game is calm but complete. Sound and vibration are optional: the game never needs them to make sense.

Using the library

No build step and no dependencies. Link the CSS files in this order and import the JS modules you need.

<link rel="stylesheet" href="design-system/css/type.css">        <!-- text styles from Figma (generated) -->
<link rel="stylesheet" href="design-system/css/base.css">        <!-- font, reset, focus ring -->
<link rel="stylesheet" href="design-system/css/components.css">  <!-- all components -->
<link rel="stylesheet" href="design-system/css/motion.css">      <!-- keyframes, reduced motion -->

Embedding over a host page

The game opens as a popup over the casino lobby. For production, mount it in a Shadow DOM root (<plinko-game>): host styles do not leak in, ours do not leak out, and the class names stay as in Figma. The tokens already target :host. Two rules: load @font-face in the main document (fonts do not load from inside a shadow root), and pass theme overrides as custom properties on the host element. The prototype skips the shadow root because its lobby is a placeholder.

Library boundary

The rule lives in Figma: every component goes into the library except sections whose name ends with "no-code" (board, controls panel, popup, win sheet, win takeover, welcome card, drawer, error card). Those are compositions and live in the game code, built from library parts. See Patterns.

Colour

Three layers. Primitives are the palettes, made in my Colour Ramp Tool. Semantic roles follow the Material 3 model (surface, on-surface, outline, scrim, action, feedback). Components hold the colours of one component or of Plinko only. Aliases always go Components → Semantic → Primitives, and the chain stays alive in CSS: --buttons-primary-default: var(--action-primary-default) → var(--magenta-500).

Palettes

Alpha ramps

Transparent colours come from alpha ramps, never from "a colour at 8 %". In code they are color-mix() of the base colour, so one change to the base updates the ramp.

Semantic roles

Bin heat

A bin sets one attribute, data-heat, and its fill, text, outline and sparkle follow (Figma: Bin heat collection with 6 modes). Colour follows the value of the prize: dull slate below the base prize, then yellow, amber and red, and pink for the edge prizes. Small prizes should not look attractive.

Component colours

Typography

Ubuntu, the site font of the host product, in 4 weights (300, 400, 500, 700), shipped as WOFF2 in the repo. 30 text styles from Figma are classes in type.css. Sizes come from tokens with a Mobile and a Desktop mode, so one class works on both. Line heights are unitless (115 % in Figma is 1.15). Titles use 2 % tracking and labels 12 %.

Spacing, radius, sizes

8 px grid with 4 px steps. The Tokens collection has a Mobile and a Desktop mode; the Desktop values start at 1024 px. The smallest supported width is 360 px.

Effects and gradients

Figma paint styles become gradient tokens (--gradient-*), and effect styles become shadow tokens (--glow-*, --shadow-*). Background blur styles use --blur-low (8), --blur-medium (16) and --blur-high (32). Buttons have no static glow: only the pulsing Drop button glows, so the one action that matters stands out.

Icons and imagery

17 icons on a 24 px grid with a 2 px stroke, in 5 sizes (xs 16, sm 20, md 24, lg 32, xl 48). Reward icons carry two small sparkles. Exported from Figma as SVG in js/icons.js; the stroke uses currentColor.

Reward art

Stylised 3D cartoon, satin and soft enamel, one soft highlight, a thin coloured rim light. Generated with ChatGPT from my prompts and style bible, then trimmed and exported (@1x, @2x, @3x, WebP). Sizes in the UI: S 48, M 80, L 160. Images are used only where code can't do the job: the ball, prize art, coins and the error art. Pegs, bins, frame, glows, rays and particles are code, so they stay sharp and react to state.

Motion

Every animation, with what a developer needs to build it: trigger, properties, from and to, duration and easing tokens, delay, reduced motion and the sound and vibration it plays with. Each card has a live demo.

Use the buttons on a card: Replay, 0.25x to slow it down, and Reduced to see the prefers-reduced-motion version. Durations and easing always come from the Motion tokens. Figma keyframes can't bind variables, so in Figma the motion uses the token values and these tokens exist only in code.

Catalogue

Drop choreography

The drop is one timeline with three tracks: what you see, what you hear and what you feel. Times are from a typical drop (the physics gives each drop its own exact times; the order never changes). The pink zone is slow motion.

Sound

Sound builds anticipation and rewards the win. The game still works fully with sound off.

  • Sound starts after the first tap (browsers block audio before it). The first tap in the game unlocks it.
  • One mute switch in the header (and in Rules and odds) controls everything. The choice is remembered.
  • Tonal and frequent sounds (taps, peg hits, ticks, chimes) are synthesised with Web Audio: they weigh nothing and follow the game (peg pitch rises row by row). Textured key moments (popup open, riser, landing, wins, ambient) are files generated with ElevenLabs.
  • Mix: one master bus at 0.9 into a compressor so peaks never clip; a separate ambient bus that ducks to 25 % under big and mega wins.
  • Peg hits are limited to 4 voices, so fast hits never stack into noise. Small random pitch changes (±2 to 3 %) keep repeats from sounding mechanical.

Press ▶ to hear a sound. Synth recipes are in js/sound.js.

Haptics

  • Vibration follows the same events as sound, but less often: no vibration on the upper rows, only the last 2.
  • One pattern at a time. A win pattern is never cut by a peg tick.
  • The Vibration switch in Rules and odds turns it off. It is hidden where the device can't vibrate.
  • Native apps would map the same events to iOS UIFeedbackGenerator and Android haptic primitives (columns below).

Physics

The result comes first. Physics only shows how the ball gets there, and it does it honestly.

1. Outcome

When the player taps Drop, the server picks the bin with the natural odds of a fair board (see Prizes and odds) and spends the ticket. The prototype does the same in model.decideOutcome() with a seeded random number generator (mulberry32). Add ?seed=42 to the prototype URL to replay the same results.

2. Path

A ball that lands in bin k bounced right k times and left 8 − k times. The engine shuffles these 8 moves at random (Fisher-Yates). Every path to bin k is equally likely, which is exactly how a real board reaches that bin. So there is no steering, no magnet and no fake near miss.

path = shuffle([+1 × k, −1 × (8 − k)])
x after row r = centre + (sum of the first r moves) × s / 2

3. Contact and flight

At each row the ball touches the top of one peg, a little to the side it will bounce to. Between contacts it flies as a projectile under gravity. The bounce sends it up a little (restitution).

contact = ( peg.x + dir × c , peg.y − √(R² − c²) ) R = peg radius + ball radius, c ∈ [3, 6] px
x(t) = x₀ + vx t y(t) = y₀ + vy₀ t + ½ g t²
vy₀ = −e × |vy impact| e ∈ [0.28, 0.42]
T = ( −vy₀ + √(vy₀² + 2 g Δy) ) / g vx = Δx / T

4. Landing and presentation

After row 8 the ball falls into its bin and settles with 2 small hops. The last 2 rows play in slow motion (time scale 0.5, 80 ms ramp) and only the bins the ball can still reach glow. Everything scales with the peg spacing s, so the board works from 360 to 430 px.

Prizes and odds

Every drop wins. Risk changes how the value is spread, not how much the player gets on average.

Odds of each bin

8 rows, 9 bins. At each row a fair ball goes left or right with p = 0.5, so the chance of bin k is binomial.

P(k) = C(8, k) / 2⁸ k = 0 … 8
edge → centre: 1/256 (0.39 %), 8/256 (3.13 %), 28/256 (10.94 %), 56/256 (21.88 %), 70/256 (27.34 %)

Value of a bin

Prizes are built on today's prize, the base unit (1x = 10 Free Spins = 2K GC value). Each bin has a multiplier m. The bin shows the amount, never the multiplier, because "×0.2" reads as a loss.

prize(k) = m(k) × base prize (for example 1.5 × 10 FS = 15 FS)
named prizes: Gift box = 12x, Treasure chest = 30x, 8K GC = 4x (collectable = 1x, rare = 3x for planning)

Average per drop

EV = Σ P(k) × m(k) ≈ 1.0x at every risk level (≈ 10 FS, 2K GC value)

Win tiers

mega = edge bin (1 in 128) big = m ≥ 2 in an inner bin (1 in 16 on Medium and High) small = everything else

The tier sets the size of the celebration (toast, sheet, takeover), not the bin position.

Prize tables

Placeholders for B2Spin: the value of 1 Free Spin (here 200 GC), the ticket rate (1 ticket per 50K GC played) and the prize-of-the-day calendar. The prize list is regional configuration. The prototype has no Sweeps Coins and no discounts.
